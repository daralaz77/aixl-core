# AIXL 0.3 — Semantic Core (executable)
Root `~/.claude/skills/aixl-core/` (Python ≥ 3.11, `.venv` with pytest + tiktoken for dev). CI (GitHub
Actions, `.github/workflows/tests.yml`) runs the full suite on every push/PR across Python 3.11 and 3.12:
https://github.com/daralaz77/aixl-core/actions/workflows/tests.yml

## Use
```bash
cd ~/.claude/skills/aixl-core
.venv/bin/python cli.py compare "TEXT A" "TEXT B"      # equivalent, similarity, drift, differences
.venv/bin/python cli.py negotiate "SENDER TEXT" "RECEIVER TEXT" [--rounds N]   # resolve a disagreement, bounded, honest ACCEPT/REJECT
.venv/bin/python cli.py mcp-serve                      # real MCP server over stdio (needs: .venv/bin/pip install .[mcp])
.venv/bin/python -m aixl.agents.a2a_server 8766         # real A2A agent over HTTP (needs: .venv/bin/pip install .[a2a])
.venv/bin/python -m aixl.agents.sender_agent --text "Close ticket #77."   # real sender agent (own process)
.venv/bin/python cli.py lab "A" "B"                    # Semantic Lab view; `cli.py serve` = web app
.venv/bin/python cli.py demo                           # the six mandatory demos
.venv/bin/python -m pytest -q                          # 170 tests (154 core + 16 A2A, optional dep)
```
Python: `import aixl; aixl.compare(a, b)`, `to_aixl`, `from_aixl`, `translate`, `semantic_diff`, `detect_drift`, `detect_ambiguity`, `detect_contradiction`, `explain`, `negotiate`, `negotiate_aixl`.

Reading the SDK's own source first (protobuf `Message`/`Task`/`Part` types, `AgentExecutor`, `DefaultRequestHandler`, `InMemoryTaskStore`, `ClientFactory`) surfaced a real architectural difference before writing any code: A2A's model is built for long-running, stateful, potentially multi-turn tasks — materially heavier than MCP's simple synchronous tool call — so this was scoped honestly to the one workflow `aixl_compare` needs (an immediate reply, never a Task); `cancel()` on the executor correctly raises `UnsupportedOperationError` rather than pretending to support a lifecycle this agent doesn't have. `A2AAdapter.validate()` runs a payload through the SDK's OWN protobuf parser (`google.protobuf.json_format.ParseDict` against the real `Message` descriptor), same "real adapter, not a mock" standard as `MCPAdapter`. **Real validation**: `tests/test_a2a_integration.py` spawns the agent as a genuine subprocess bound to a real socket, polls its real agent-card endpoint until ready, then drives it with the SDK's own `ClientFactory`/`Client` over an actual JSON-RPC/HTTP round-trip — 3/3 pass, including a real CRITICAL_DRIFT case matching `aixl_compare`'s own reasoning. `a2a-sdk[http-server]` is optional (`pip install .[a2a]`), core suite skips cleanly without it. Honest scope at the time: n=1 — only this project's own test client has connected, unlike MCP's 3-vendor confirmation; only `aixl_compare` exposed, not `aixl_translate`/`aixl_negotiate`; A2A's streaming/push-notification/multi-turn features entirely unexercised; REST/OpenAPI/GraphQL remain unimplemented. **E-A2A-NEGOTIATE** (2026-09-30, same day, user asked to review the "A2A is heavier" finding and propose a creative fix; chose "give A2A's Task model the one AIXL capability that genuinely needs it" over 2 alternatives — a thinner hand-rolled server, discarded as reintroducing the exact "plausible-looking mock" risk this project avoids; a cosmetic bootstrap simplification, discarded as not addressing the real finding): `aixl_negotiate` is now a genuine multi-turn A2A Task, not a single reply. Ordinary disagreements still auto-resolve in one call exactly like `negotiate()`; an irreversible-action disagreement pauses the Task (`TASK_STATE_INPUT_REQUIRED`) and asks a human which candidate is correct, resuming with their answer — making real a claim (`negotiate()`'s REJECT message: "requires human confirmation") that previously had no actual mechanism behind it. Verified the native pause/resume mechanism exists by reading the SDK's own source (`TaskUpdater`, `context.current_task`, `task.metadata.MergeFrom`) before writing any code. **Two real bugs found by actually running the round-trip, not by reading the code**: (1) the human's answer was applied only to the receiver's belief, leaving the sender's own value unchanged, so resuming kept reporting the identical disagreement forever — fixed by pinning the human-confirmed value on BOTH sides; (2) the irreversible-action check was ordered before the empty-sender-value check — the SAME mistake made and fixed earlier that same day merging `negotiate()`/`negotiate_autonomous_async()` (AUDIT.md finding #4) — causing an out-of-vocabulary sender case to wrongly pause instead of REJECTing outright; fixed by restoring the correct order. `tests/test_a2a_integration.py` grew to 8 tests (ordinary auto-resolve, irreversible pause, two full pause→resume round-trips proving the human's answer genuinely drives the outcome, and the empty-sender REJECT case). 170/170 total, confirmed in clean venvs on Python 3.12 and a real Python 3.11 install. Still n=1; `cancel()` on a negotiation task still unsupported; no third-party client has driven this multi-turn flow yet.
