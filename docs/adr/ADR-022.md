# ADR-022 — Package layering: what `legacy02`, `semantic/` and `atoms/` are, and how the layering is enforced

**Status: ACCEPTED, option A applied (2026-10-08, owner's choice).** Options B and C remain open and are not blocked by A.

## Problem
The cleanup roadmap (`docs/CLEANUP_ROADMAP.md`, Phase 6) assumed three things: that `legacy02` is dead weight that can be retired, that the three semantic
representations (`core/`, `semantic/`, `atoms/`) are tangled, and that the package graph has structural cycles. The measurements below correct all three.

## Evidence (measured 2026-10-08)
**1. `legacy02` is not legacy: it is the foundation of the product path.** It is a leaf (imports nothing from `aixl`) and is imported by `core`, `translators`,
`serialization` and `telegraph`. What the rest of the code takes from it:

| From `legacy02` | Used for |
|---|---|
| `core.encoder.encode`, `core.parser.parse`, `AixlError` | the AIXL wire syntax itself (`serialization/aixl_codec.py` delegates entirely) |
| `core.semantic_frame.SemanticFrame`, `core.normalizer.normalize` | the frame the 0.3 graph is built from |
| `protocol.atoms.derive_intent/derive_goal`, `protocol.versions.SUPPORTED` | intent/goal derivation, version check |
| `translators.natural_to_semantic` tables: `DATA_RX` (10 uses), `ENTITY_RX` (9), `MONTHS` (7), `LANGS`, `ACTION_RX`, `REL_RX`, `PLACES`, `COUNTRIES`, `NEG_BEFORE`, plus `analyze` | the rule vocabulary and the 0.2 analyzer the 0.3 translator extends |

`import aixl` pulls in 8 of its 14 files. "Retire" is therefore impossible without moving real code; the name is the only legacy part.

**2. The package graph is nearly acyclic.** Import direction today: `legacy02` ← `serialization`, `core`, `translators`; `core` ↔ `translators` only through
3 lazy (function-level) imports (`core.lexicon_gaps`, `core.semantic_graph`, `translators.natural_to_semantic`); `semantic` → `core`; `atoms` → `semantic`;
`agents`, `api`, `adapters`, `guard` → `core`/`serialization`. At import time the only cycle group is the normal `__init__`↔submodules one inside `semantic`.

**3. The experimental tracks are already isolated from the main path.** `import aixl` (public API) reaches `core`, `translators`, `serialization`, `legacy02`,
`negotiation`, `api` and **nothing from `semantic/` or `atoms/`**. `semantic/` enters only through `aixl/mcp_server.py → hybrid_protocol` (the published hybrid MCP tool,
`docs/HYBRID_MCP.md`); `atoms/` only through `cli.py atoms-*` and the benchmarks.

| Package | Size | Tests referencing it | Role |
|---|---|---|---|
| `core` + `translators` + `serialization` | ~2.7k LOC | 21 / 14 / 10 files | the product (graph, comparator, gate, fingerprint, codec) |
| `legacy02` | 1.0k | 4 | foundation (wire syntax, frame, rule tables) — misnamed |
| `semantic` | 1.5k | 2 | the 0.3-R track; its "safer than the arbiter" claim was NOT established (`docs/` blind18 result) |
| `atoms` | 1.6k | 1 | in-progress atoms layer (agreement with natural text 33% → 59%) |

## Dry run of candidate architecture rules (all PASS today, so enforcing them costs no code change)
R1 `legacy02` imports nothing from `aixl`. R2 `core`, `translators`, `serialization`, `api`, `gate`, `envelope`, `telegraph` never import `semantic` or `atoms`.
R3 `semantic` imports only `core`/the root API; `atoms` only `semantic`. R4 no import-time cycles outside a package's own `__init__`.

## Options
**A. Document and enforce, change no runtime code (recommended).** Add `docs/ARCHITECTURE.md` layering section with status labels (stable foundation / product /
experimental), module docstring banners on `semantic/` and `atoms/` ("EXPERIMENTAL: not on the `import aixl` path"), a note in `legacy02/__init__.py` ("historical name;
this is the 0.2 frame/wire foundation, not dead code"), and an **architecture fitness test** (`tests/test_architecture.py`) that fails if R1–R4 are ever broken.
Cost ≈ ½ day, zero runtime risk, zero import-path change, frozen benchmarks and external users unaffected.

**B. A + rename for honesty.** Rename `legacy02` → e.g. `aixl/frame` and move `semantic/`, `atoms/` under `aixl/experimental/`, leaving `sys.modules` alias shims at the old paths.
Fixes the misleading names. Cost ≈ 2–3 days; touches ~15 import sites, 4+ test files, docs; every frozen `CODE_FREEZE.json` hash for `semantic/*` changes (those rounds are already
void, see roadmap Phase 4); external code importing the old paths depends on the shims.

**C. A + split the experimental tracks into an optional distribution.** `semantic/` and `atoms/` become an extra (`pip install aixl-core[experimental]`), with the hybrid MCP tool
registered only when installed. Smallest default footprint and an honest product surface. Cost ≈ 3–5 days; removes a currently published MCP tool from the default server — a product decision,
not a cleanup.

## Decision
Recommended: **A now**; revisit B only if the misleading names cause real confusion for contributors; C only if the hybrid tool is judged not worth shipping by default. Evidence for A over B/C: the
measured graph is already acyclic and already isolates the experimental code, so what is missing is *enforcement and labels*, not restructuring.

## Consequences
A: layering becomes a tested property; new contributors get the status labels in the code itself. Nothing moves. B/C: larger churn, shims to maintain, and a release note.

## Compatibility
A: fully compatible. B: compatible only via alias shims. C: removes the hybrid tool from default installs.

## Corrections to the roadmap's own hypotheses (recorded for honesty)
H5 "legacy cannot be deleted because of two sources of truth" → refined: it is not a duplicate, it is the single source of the rule tables and the wire syntax. H12 "three tangled representations"
→ refuted: they are layered and isolated; the untangling cost is in naming and enforcement.

## Applied (option A)
- `tests/test_architecture.py`: R1–R4 over the real import graph (AST), the rule engine itself tested against injected violations, and R5 (plain `import aixl` loads no `aixl.semantic` / `aixl.atoms`, checked in a clean interpreter). Verified by temporarily injecting a product→semantic import and a legacy02→core import: both fail the test with the offending module named.
- Status banners: `aixl/legacy02/__init__.py` (stable foundation, historical name), `aixl/semantic/__init__.py` and `aixl/atoms/__init__.py` (EXPERIMENTAL). `aixl/atoms/` had **no `__init__.py`** (an implicit namespace package); adding one makes it a regular package — imports are unchanged, but `setuptools.find_packages` (which only picks up directories that contain an `__init__.py`) should now include it in built distributions, where it was silently left out before. **Verified 2026-10-08 with setuptools 84.0.0:** `find_packages(include=['aixl*'])` returned 13 packages without the `__init__.py` and 14 with it; a built wheel (`aixl-0.5.0`, 82 files) now contains the 10 `.py` files of `aixl/atoms/`. The `aixl/atoms/data/` JSON files are NOT in the wheel (no package-data configuration), so `atoms` could not read its data from an installed wheel. **Fixed the same day** with `[tool.setuptools.package-data] "aixl.atoms" = ["data/*.json"]`: loaded from the unpacked wheel outside the repo, `registry._load_learned()` returns 93 concepts and `data/aliases.json` is found, identical to the repo; the wheel built without the fix loaded 0 concepts and no aliases, **silently** (`_load_learned` returns `[]` when the file is missing). Guard: `tests/test_packaging.py`.
- `ARCHITECTURE.md`: "Package layering and status" section.
