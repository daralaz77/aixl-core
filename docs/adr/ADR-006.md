# ADR-006: Relative time resolves only at canonicalization, against an explicit date
Status: Accepted

**Problem.** 'mañana' must not become a date without a clock, yet 'mañana' and the literal date should compare equal when the clock is known (§18).

**Decision.** `TIME` nodes keep their token; `canonical(today=…)` resolves day/month/year tokens to ISO values; `today` defaults to the system date but tests and fingerprints should pin it. Week-level tokens stay unresolved.

**Alternatives.** Resolve at parse time; never resolve.

**Reasoning.** Resolving at canonicalization covers the rule route and LLM-encoded lines alike (found missing by set 7). Week ranges have no AIXL literal; inventing one would add information.

**Consequences.** Fingerprints depend on `today` for relative tokens; store it next to persisted fingerprints.

**Compatibility.** Documented in LIMITATIONS #4.
