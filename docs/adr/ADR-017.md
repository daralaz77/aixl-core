# ADR-017 — Residue canonicalizer + per-side completeness check — STATUS: DESIGN (experiments run, nothing shipped)

## Problem (evidence)
ADR-016 step 2 made loss visible (`R:`), and on blind10 the LLM route went from 58.9 % to 1.1 % false-EQUIVALENT — but **proven equivalence fell from 55/60 to 3–5/60**, because encoders copy residue in the text's original wording, so a faithful translation ("to the CFO" / "al director financiero") yields different literals. What are residue items? Measured on 743 real items (blind10, card 0.5): **76–93 % are open noun phrases**, only 15–25 % are numbers/units/weekdays/durations. A deterministic lexicon alone cannot be the main path.

## Experiments (120 real pairs: 60 EQUIVALENT + 60 NOT_EQUIVALENT, residue lists + action codes only; Sonnet; `benchmarks/residue_canon_eval.py`, data in `data/blind10/rc_*`, `rj_*`)
| Option | Mechanism | EQUIVALENT recovered | NOT_EQUIVALENT kept different | false-SAME |
|---|---|---|---|---|
| A | each side canonicalized INDEPENDENTLY to an English typed key (`recipient:cfo ; by:mon`), then key equality | 54/60 | 53/60 | 7/60 |
| B | an LLM judge decides SAME/DIFFERENT/UNSURE per pair | 53/60 (6 DIFFERENT, 1 UNSURE) | 53/60 | 7/60 |
| C | closed bilingual lexicon | not run: covers ≤25 % of items (typed ones only) | | |
**Key finding — the 7 false-SAME are the same cases in A and B and are NOT canonicalizer errors**: in ≥6 of 7 the residue is literally identical or empty (`'Refund'`/`'Refund'`, `[]`/`[]`), i.e. the differing detail ("50 vs 500 boxes", "room B vs C", "weekly vs daily") never reached R — an encoder loss upstream. The canonicalizer cannot detect what was never written; the **completeness check** must.
Pipeline simulation (card 0.5 + per-side completeness + A keys, blind10, 120 pairs, development signal): false-EQUIVALENT 2/60 in every setting; proven EQUIVALENT 5 → 24 → 37 → 45 /60 as the tolerated number of unaccounted words per text goes 0 → 3. The 2 false cases are a lexicon gap, not tolerance: single-letter values ("sala **B**/**C**", dropped because tokens < 3 chars are ignored) and ordering words ("tres días **antes**/**after** del vencimiento", treated as function words so never checked against the graph). Tolerance is therefore NOT a design parameter (it would be tuned on seen data); it must be replaced by structure (below).

## Decision
1. **Completeness is per side; equality is per canonical form.** A text is `COMPLETE` iff (a) every content word is accounted by an atom, a lexicon or an R item, **including 1–2 character tokens and digits**, and (b) every closed-class *structural marker* in the text (before/after/antes/depois, only/solo/apenas, all/todos, except/salvo, not/never/nunca, more/less than, every/cada, at least/at most) is reflected in the graph structure (negation, BEFORE/AFTER, SCOPE, QTY comparator, FREQ). Marker lexicon is closed and small (ES/EN/PT), deterministic, replaces the function-word blind spot. An INCOMPLETE side forces INCONCLUSIVE; no tolerance parameter.
2. **Canonicalizer = option A, independent per side, cached.** A separate step (or card 0.6 asking the encoder to emit canonical keys directly — to be A/B'd) maps each side's residue to typed items: `NUM/QTY(value,unit)`, `DAY`, `DUR`, `BY`, `FREQ`, `RECIPIENT`, `CHANNEL`, `SCOPE`, `OBJ` … in lowercase English. Independence is the safety property: the canonicalizer never sees the other side, so it cannot "agree" for convenience. Keys are stored in the AIXL line as typed R items (`R:"recipient:cfo","by:mon"`), so `fingerprint` (ADR-015) stays deterministic once keys exist; cache key = sha256(normalized text + model id + prompt id).
3. **Typed items are verified deterministically (tier 1), the LLM cannot override them**: numbers (digits/number words ES/EN/PT), units, weekdays, months, durations, simple deadlines are parsed by the Core and compared exactly; a mismatch there ⇒ NOT_EQUIVALENT even if the LLM key says same.
4. **Judge (option B) only as arbiter**, for pairs that are COMPLETE on both sides, equal on every non-residue dimension and tier-1 typed items, but whose open-phrase keys differ. `DIFFERENT` is always honored (downgrade); `SAME` is honored only with 2-of-2 agreement (two prompts or two models) and is recorded in a decision memo (pair hash → verdict) so it is replayable. Never used to override INCOMPLETE.
5. **Asymmetry rule (safety):** evidence to *separate* is accepted from any single source; evidence to *join* needs (completeness ∧ tier-1 agreement ∧ key equality or consensus).

## Alternatives rejected
* Pairwise judge as the main path (B): equal accuracy to A in the experiment, but costs one call per *pair* (O(n²) over a corpus), is non-deterministic per run, and sees both sides (can rationalize equality). Kept as arbiter.
* Embedding similarity: ADR-002.
* Raising the unaccounted-words tolerance: increases proven equivalence mechanically (5→45/60) but is tuned on seen data and silently reopens loss; rejected.
* Pure lexicon (C): coverage ≤25 % of items; used for tier 1 only.

## Compatibility / versioning
Additive to AIXL 0.5 (typed R items are still `R:`); old messages and 0.4 verdicts unchanged while `inconclusive` is off. New status `INCOMPLETE` appears as a warning (`INCOMPLETE_ENCODING`), and as INCONCLUSIVE when the flag is on. Fingerprint of a 0.5 line with canonical keys differs from the 0.4 one by construction.

## Validation plan (gates fixed before implementing; judge = blind11, frozen sha256 b22b863b…, evaluated ONCE after implementation; encoders Sonnet AND Haiku because the author is Sonnet)
1. false-EQUIVALENT ≤ 5 % of non-equivalent pairs (blind10 development signal: 1–2 %).
2. proven EQUIVALENT ≥ 70 % of equivalent pairs (blind10 signal after the marker fix is open: 45/60 = 75 % only with an unprincipled tolerance of 3 — the structural check must reach ≥ 70 % WITHOUT tolerance, or the gate fails and is reported).
3. 0 regressions: 453 tests, 5×100 ≥ 99 %, sil_security 57/57.
4. Report separately: Sonnet vs Haiku encoder; completeness-flag rate; judge invocation rate; cost per 100 pairs.
5. If gate 2 is not met, keep INCONCLUSIVE off by default and document (ADR-016 rule).

## Risks
* Canonicalizer variance between independent calls ("warehouse manager" vs "warehouse supervisor"): measured 54/60 for A; residual 10 % goes to INCONCLUSIVE (safe) or arbiter.
* Closed marker lexicon is ES/EN/PT only; other languages ⇒ always INCOMPLETE ⇒ safe but useless.
* Experiments used residue lists, not the full pipeline end-to-end, and were run on the same seen set used to diagnose: the numbers are optimistic until blind11.
* Cost/latency: one extra LLM call per side (cacheable); offline fallback = rule-based route + INCONCLUSIVE.

## Implementation order (stop when a gate fails)
1. Completeness check (token coverage incl. 1–2 char tokens/digits + structural markers) with tests from the 2 known false cases; measure on blind10 rules + LLM routes.
2. Tier-1 typed parsers (number words, weekdays, durations, units) with unit tests in ES/EN/PT.
3. Canonicalizer step (A) + cache + typed R items in the codec; compare on keys.
4. Arbiter (B) with 2-of-2 consensus and decision memo.
5. Card 0.6 (encoder emits keys directly) A/B vs the separate step.
6. Freeze, run blind11 once with both encoders, publish results.

## Step 1 implemented (2026-10-02) — per-side completeness + structural markers (`aixl/core/completeness.py`)
Shipped: `check_completeness(text, graph)` (content-word coverage INCLUDING 1–2 char tokens and digits, token-set membership instead of substring; closed-class function words ES/EN/PT; first imperative verb accounted by the ACTION atom — declared limitation), `extract_markers` / `marker_conflicts` (closed marker lexicon: NEG, BEFORE, AFTER, ONLY, ALL, EXCEPT, MORE, LESS, EVERY), `annotate(graph, text)`; `compare_graphs` (flag on, both sides annotated): opposed markers (before/after, more/less) ⇒ NOT_EQUIVALENT with a `MARKERS` difference; an incomplete side or other marker mismatch ⇒ INCONCLUSIVE (`INCOMPLETE_ENCODING`). `residue_key` now keeps short content tokens ("sala B" ≠ "sala C"). Card 0.6 = 0.5 + rule "keep quantifiers/ordering/scope words in R". 461 tests (8 new: `tests/test_completeness.py`), default behaviour unchanged (flag off). Evaluator: `python -m benchmarks.completeness_eval GLOB [--keys]`.
**Measured on blind10 (120 pairs, seen set = development signal), no tolerance parameter:**
| encoding | sides complete | false-EQUIVALENT (of 60) | EQUIVALENT proven (of 60): raw R / A keys |
|---|---|---|---|
| card 0.5 | 185/240 | 0 | 2 / 17 |
| card 0.6 | 188/240 | 0 | 2 / 16 |
(before this step, same data, tolerance 0: false-EQUIVALENT 2/60; both known failures — "sala B/C" and "antes/after" — are now caught by construction, with tests.)
**Gate status:** gate 1 (false-EQUIVALENT ≤ 5 %) met on the development set. **Gate 2 (proven EQUIVALENT ≥ 70 % without tolerance) is NOT met and will not be met by this approach alone: 16/60 = 27 %.** Why the 60 true-equivalent pairs are not proven (card 0.6): **30 have an incomplete side** — mostly verbs outside the verb table not in first position (restart, merge, recibir, submit, reportar, confirmar…) and nouns the lint cannot match across the encoder's own lemma/language (proveedor, backup, pacientes); **10 have a marker mismatch between faithful paraphrases** ("all" vs "every", "older than one year" vs "more than 12 months", "under $1,000" vs "menores a mil dólares" read as LESS vs none) — a closed marker lexicon cannot know these are the same; **20 pass completeness and markers** and then reach the residue keys (A recovers 16 of them, 11 are lost to key variance).
**Reading:** the safety side of the hypothesis now has evidence (0 false-EQUIVALENT on the development set, no tolerance). The usefulness side does not: proving equivalence of free-text paraphrases requires understanding verbs and phrases that a closed lexicon cannot cover, and moving that judgment into an LLM brings back non-determinism. The honest options are (1) accept INCONCLUSIVE as the normal outcome for open text and use AIXL where texts are drawn from a controlled vocabulary or paired with the arbiter (ADR-017 §4), (2) extend the verb table with a POS-free per-action budget (rejected: tolerance in disguise), (3) let the LLM canonicalizer also emit verb/marker classes as typed keys that the Core verifies deterministically (untested). None is implemented; blind11 remains unevaluated.

## Experiment: option 2 — typed keys (verbs/terms lemmas + markers + typed values) verified deterministically (2026-10-02)
Setup: 480 texts (240 pairs: 60 EQUIVALENT, 60 NOT_EQUIVALENT, 60 PARTIALLY_EQUIVALENT, 60 CONTRADICTORY from blind10), each canonicalized INDEPENDENTLY by Sonnet (rules in `data/blind10/` prompt, outputs `ex2_out_*.jsonl`). The Core verifies without any LLM (`benchmarks/typed_keys_eval.py`): V1 declared surface words occur in the text; V2 every content token is covered; V3 every declared marker has textual evidence and every marker the deterministic extractor finds is declared. Invalid side ⇒ INCONCLUSIVE; equal keys ⇒ EQUIVALENT; opposed markers ⇒ NOT_EQUIVALENT.
**Result: FALSE-EQUIVALENT 0/180 (0.0 %); EQUIVALENT proven 6/60 (10.0 %)**; of the 60 true pairs: 33 DIFFERENT keys, 21 INCONCLUSIVE (70/480 sides invalid: 47 uncovered tokens, 15 marker without evidence, 7 omitted marker, 1 undeclared word). The verifier did its job (nothing false got through, even for PARTIAL/CONTRADICTORY pairs, the harder classes).
**Why recall is 10 %: lemma variance between independent calls is real synonymy**, not noise: review/check, install/deploy, increase/upgrade, main/primary, answer/respond, past/last, 7 d vs 1 w, "todas" (ALL) present on one side only. Of the 33 differing pairs only 1 differs in markers+typed alone; 31 involve verb or term lemmas. A bag of lemmas also loses roles (send A to B ≈ send B to A) — not exercised by this set but a known false-EQUIVALENT route. Typed normalization (7 d = 1 w) is a cheap deterministic fix worth a few points; synonymy is not.
**Combined measure (gate + arbiter), same data:** pairs that pass per-side completeness and marker checks AND whose residue lists the B-judge calls SAME: card 0.5 → EQUIVALENT proven 19/60 (32 %), false-EQUIVALENT 5/60 (8.3 %); card 0.6 → 19/60 (32 %), 4/60 (6.7 %). The judge saw residue only, so it re-admits some false-SAME; a judge that sees the full texts was not tested.
## Conclusion for ADR-017 (honest)
* **Gate 2 (≥ 70 % proven EQUIVALENT) is not reachable with any design tested**: independent canonicalization 10–27 %, gate + residue judge 32 %. Gate 1 (false-EQUIVALENT ≤ 5 %) holds only for the deterministic designs (0 %); the judge variant is 6.7–8.3 %.
* What *is* demonstrated: a verifiable safety layer — loss made visible (R, completeness, markers) and deterministic separation — that takes false-EQUIVALENT from 47–59 % (AIXL 0.4 on open text) to 0 % at the price of INCONCLUSIVE on most true paraphrases.
* What is NOT demonstrated: that AIXL can prove equivalence of open-domain paraphrases. Proving "same meaning" across free wording requires synonymy judgment; as soon as an LLM supplies it, determinism and verifiability are weakened. This is a candidate FUNDAMENTAL limit of the hypothesis for open text (master prompt §37), not just an engineering gap.
* Recommended scope for AIXL 0.5: (1) use as a **non-equivalence / loss detector with INCONCLUSIVE as the honest default** for open text; (2) full equivalence proofs where the vocabulary is controlled (the 5×100-style domain: 99.4 %); (3) optional human or LLM arbiter on INCONCLUSIVE pairs, recorded as a decision memo, never silently. Not tested yet: an arbiter that sees the full original texts; whether adding a synonym lexicon built from arbiter decisions converges (cold start measured here: poor).

## Experiment: full-text arbiter (2026-10-02) — `benchmarks/arbiter_eval.py`, data `data/blind10/arb_*`
Setup: 240 pairs (60 EQUIVALENT / 60 NOT_EQUIVALENT / 60 PARTIALLY_EQUIVALENT / 60 CONTRADICTORY, blind10), arbiter sees BOTH ORIGINAL TEXTS only (no atoms, no residue, no labels), strict rules written before looking at any output ("one added/dropped/changed detail ⇒ DIFFERENT; synonyms, translation, number words ⇒ fine"), two independent models (Sonnet, Haiku), 4 agents, 0 UNSURE.
| configuration | EQUIVALENT proven (of 60) | false-EQUIVALENT (of 180) |
|---|---|---|
| Sonnet alone | 56 = 93.3 % | 0 |
| Haiku alone | 60 = 100 % | 0 |
| consensus 2-of-2 (SAME only if both) | 56 = 93.3 % | 0 |
| PIPELINE: per-side completeness + markers + consensus | **20 = 33.3 %** | 0 |
By author (to rule out self-judging bias): Opus-authored (judges ≠ author) 30/30 SAME on equivalents, 0/90 SAME on non-equivalents for BOTH judges; Haiku-authored: Sonnet 26/30, Haiku 30/30, 0/90 false for both. The two judges disagree on 4/240 pairs (all on equivalent pairs: Sonnet more conservative).
**Reading (this changes the earlier conclusion):** the "recall ≈ 10–32 %" ceiling was a property of *AIXL-side* canonicalization, not of the task: a strict LLM that reads both full texts separates the four classes on this set with 0 false-EQUIVALENT and 93–100 % recall. Within AIXL the completeness gate is what costs the recall (93 % → 33 %) without buying safety on this set (0 false-EQUIVALENT either way).
**What this does NOT show (declared):** (1) 240 pairs on a SEEN set; blind11 is the clean judge and has not been run; (2) the arbiter's prompt was fixed in advance but its strictness may cost recall elsewhere or overfit this author style; (3) determinism/repeatability across runs not measured (same pair, same prompt, N runs) — essential for §3.3; (4) no adversarial pairs (the sil_security HARD tier: homoglyphs, injected instructions, hidden negations) — an arbiter LLM is itself an injection target; (5) cost: one LLM call per pair (O(n²) over a corpus), no offline mode; (6) AMBIGUOUS class not tested; (7) it is a plain "ask a strict LLM to compare" result: **no metric collected so far shows AIXL adds correctness on top of it.** AIXL's possible value is elsewhere (cacheable canonical fingerprints, machine-checkable structure, audit trail, controlled-vocabulary exact proofs at zero marginal cost, cross-system exchange) and has not been measured against this baseline.
**Decision for AIXL 0.5 (proposed, not implemented):** treat the full-text arbiter as the BASELINE every AIXL mechanism must beat. A mechanism stays only if it (a) lowers false-EQUIVALENT below the arbiter's on an adversarial set, or (b) gives determinism/cost/offline guarantees the arbiter lacks, measured. The completeness gate should be reclassified from "gate for EQUIVALENT" to "diagnostic / cheap pre-filter" unless adversarial tests show it catches what the arbiter misses.
## Next experiments (ordered, none run): (1) arbiter determinism: 5 repeats × 240 pairs, flip rate; (2) arbiter on the sil_security HARD tier + injection pairs, with and without the gate; (3) blind11 once, all arms (0.4 rules, AIXL pipeline, arbiter alone, arbiter + gate) with Sonnet and Haiku encoders/judges; (4) cost/latency per 1000 pairs.

## Experiment: adversarial pairs against the full-text arbiter (2026-10-02) — `benchmarks/adversarial_eval.py`, data `data/blind10/adv_*`, `redteam.jsonl`
Set (198 pairs): (a) RED-TEAM by Opus (told the arbiter's rules, asked to fool it): 70 NOT_EQUIVALENT in 9 families (injection aimed at the judge, hidden negation, scope shift, number locale, unicode homoglyphs/lookalike digits, role swap, conditional flip, polarity verbs, partial commit) + 40 EQUIVALENT controls that look suspicious; (b) the project's own sil_security HARD (57, must be flagged) and CONTROL (31). Same arbiter rules as before (unchanged), Sonnet and Haiku independently, texts presented as DATA.
| arm | RED-TEAM attacks judged SAME (of 70) | OWN-HARD SAME (of 57) | RED-TEAM controls SAME (of 40) | OWN controls SAME (of 31) |
|---|---|---|---|---|
| Sonnet alone | 2 | 0 | 39 | 31 |
| Haiku alone | 4 | 0 | 39 | 31 |
| consensus 2-of-2 | **1** | 0 | 39 | 31 |
| AIXL rules route only (INCONCLUSIVE on) | 17 (proves EQUIVALENT for 6/8 role swaps, 6/8 unicode, …) | 0 | 0 | 31 |
| consensus + AIXL "veto" (rules NOT_EQUIVALENT ∨ contradiction ∨ obfuscation) | 0 | 0 | **13** | 31 |
| consensus + AIXL strict (rules must prove EQUIVALENT) | 0 | 0 | 0 | 31 |
**Reading.** (1) The arbiter is robust: the 8 injection pairs (fake verdict markers, notes to the reviewer) fooled neither judge (0/8 SAME for both) — the "DATA, never instructions" framing worked at this n; the single consensus miss is `1,000 kg` (EN) vs `1,000 kg` (ES, where the comma is the decimal separator) — arguably an AMBIGUOUS pair, not a clean error. (2) Single judges do fail: Haiku was fooled by 3/8 Cyrillic-homoglyph pairs (e-mail/user names with a look-alike letter) and 1 more; Sonnet by 1 hidden negation and 1 locale pair. Consensus removes all but one. (3) The AIXL rules route is NOT a useful separator or prover on open text: as a veto it wrongly rejects 26 of 39 correctly-SAME controls; its only separating signal that never misfired is the input-obfuscation detector (`sanitize_input`), with 0 false vetoes on 71 benign pairs.
**Post-hoc analysis (declared: chosen after seeing which signals misfired, on the same data — needs blind11):** arbiter + NARROW veto (obfuscation findings only): Haiku alone 4 → 1 false-SAME at 0 cost (70/71 equivalents kept, same as without), Sonnet alone 2 → 2, consensus 1 → 1. So a deterministic sanitizer lets the cheaper single judge reach consensus-level safety on the homoglyph class; it adds nothing once two judges agree. Not caught by the sanitizer: look-alike digits (`1OO5`/`1005`, `v2.l`/`v2.1`) — the arbiter caught those; and it only knows the common Cyrillic/Greek confusables, which the red-team author happened to use.
**What this changes (answering "does AIXL add value over the arbiter?"):** the only measured contribution so far is a deterministic, zero-cost input-hygiene layer (obfuscation detection + canonical text normalization) that substitutes for a second LLM judge on one attack class. The semantic part (completeness, markers, residue, rules route) did not beat, and mostly degraded, the arbiter. Controlled-vocabulary exact proofs (99.4 % on the own set, offline, zero marginal cost, deterministic) remain a real property but were never compared against an arbiter on cost/latency.
**Limits:** n is small (70 attacks / 71 controls; per family 7–8); one red-team author, who knew the arbiter's rules; same two judge models as the previous experiment; no repeatability runs; ground truth of the locale pair is debatable; blind11 not yet run; arbiter prompt unchanged on purpose (no tuning), so recall/precision may shift with other wording.

## Experiment: repeatability of the full-text arbiter (2026-10-03) — `benchmarks/repeatability_eval.py`, data `data/blind10/rep_*`
Setup: 82 pairs = the 10 BOUNDARY pairs (a judge erred or the two judges disagreed in the earlier blind10/adversarial runs) + 72 background pairs (36 blind10, 36 adversarial/controls, sampled from pairs both judges got right before). Same arbiter rules, same texts; 5 independent passes per model (a fresh agent each, line order shuffled per pass); 410 judgments per model.
| | correct per pass (of 82) | pairs whose verdict flipped across 5 passes |
|---|---|---|
| Sonnet | 77, 76, 76, 76, 76 | **1/82 (1.2 %)** |
| Haiku | 78, 79, 77, 77, 78 | **5/82 (6.1 %)** (+1 pair with a dropped output line in one pass) |
| consensus 2-of-2 | 76, 76, 76, 75, 76 | **1/82 (1.2 %)** |
Consensus false-SAME per pass: 1, 1, 1, 1, 1 — **the same pair every time** (the locale-comma pair `1,000 kg`). 6 pairs were wrong in ALL 5 consensus passes (5 equivalent pairs judged different, e.g. a PT/EN paraphrase of "print labels for the main catalog" where one side adds "all items", plus that locale pair).
**Reading:** the arbiter's errors are overwhelmingly SYSTEMATIC (the same pair wrong every time), not random noise: run-to-run flips affect 1.2 % of pairs for Sonnet and for the 2-of-2 consensus, 6.1 % for Haiku. So repeatability is high enough that a recorded decision memo (pair hash → verdict + model + prompt id) makes the arbiter *replayable* at low cost, and consensus damps Haiku's instability. It is NOT deterministic in the strict sense of master prompt §3.3: a given pair can flip (Sonnet flipped `a036` once in five), so the verdict must be stored, never re-derived, if reproducibility is required.
**Limits (declared):** 82 pairs; only 10 are boundary pairs, 72 were sampled from previously-correct pairs, which UNDER-states instability (selection toward easy items); 5 passes, one temperature setting we do not control (agents), same two model families; a label I would now question: `a036` (a control containing a "reviewer's note: urgent" besides the instruction) is arguably NOT equivalent, so its flips are partly label noise; one output line was dropped by Haiku in one pass (format reliability: 1/410) — a production arbiter needs output validation and retry.

**The three arbiter errors (all inspected):** (1) "Desative as contas de ex-funcionários…" vs "Delete former employees' accounts…" — Haiku said SAME (disable ≠ delete, the severe kind of error), Sonnet DIFFERENT, so consensus caught it; (2) "…6 p.m. on weekdays" vs "…6 p.m. local time on weekdays" — Haiku SAME, Sonnet DIFFERENT; (3) "tesis" (theses) vs "term papers" — BOTH said SAME; the author labelled it NOT_EQUIVALENT, but the difference is a translation nuance and the label is debatable.
**Conclusions (as measured, one author, one set of 300):**
1. The original blind10 finding replicates on a fresh set: the AIXL 0.4 rules route judges ~41 % of non-equivalent pairs EQUIVALENT. AIXL's own safety layers remove that error (0.6 %–2.2 %) but prove NO equivalence on open text (0 %) — the completeness-based pipeline is, on this set, a pure "never say equal" detector, worse in usefulness than blind10 suggested (there it proved 2–17/60 depending on keys).
2. A strict full-text LLM arbiter, 2-of-2, passes both gates with large margin (100 % / 0.6 %), also on an unseen author. Consensus matters: each single judge made at least one error the other did not (Haiku 3, Sonnet 1).
3. The post-hoc obfuscation veto is neither confirmed nor refuted (this set has no homoglyph attacks); on blind10-adversarial it fixed Haiku-alone only.
4. Rules-route ambiguity detection is weak on free text (16.7 % recall, 11.7 % false-flag): it should not be advertised for open-domain input.
5. Same-family caveat: the author is Sonnet, but Haiku (not the author) matches Sonnet's 100 % recall and has more false-SAME, so there is no sign of author-judge inflation; Opus- and Haiku-authored blind10 gave the same picture.
**Consequence for the master prompt's central question (§45 "does the receiver understand essentially the same thing the sender meant?"):** for open-domain instructions the evidence supports an LLM-arbiter-with-consensus + stored decision memo as the working answer; AIXL's semantic layers did not contribute accuracy on top and, as designed, cannot prove equivalence of paraphrases. What remains for AIXL to demonstrate (not measured here): zero-marginal-cost deterministic proofs in a controlled vocabulary, cost/latency per 1000 pairs, fingerprints/caching of arbiter decisions, interchange format and audit trail.

## MEASUREMENT: cost and latency per 1000 pairs (2026-10-03)
Sources: (1) local wall-clock of the deterministic path on this Mac (CPython, single thread, 400 controlled-vocabulary pairs of the 5×100 set); (2) token volumes counted with `tiktoken cl100k` as a PROXY tokenizer (not Claude's: expect ±20 %) over the real blind11 inputs/outputs; (3) agent-reported usage/duration from the 16+ arbiter and encoder runs (these include harness overhead: reading files, writing output, ~58k fixed tokens per agent for Sonnet and ~40k for Haiku, from a two-point fit over 82- and 120-pair runs); (4) prices from the claude-api skill table cached 2026-09-25: Sonnet 5.5 $2 in / $10 out per MTok (cache read $0.20), Haiku 4.5 $1 / $5, Batch API −50 %. No live API call was made for this measurement; all dollar figures are ESTIMATES.

**Scaling (the structural difference):** the arbiter is per PAIR — all-pairs over N texts is N(N−1)/2 calls: N=1 000 → 5·10⁵ pairs ≈ $81 (Sonnet) / $141 (2-of-2); N=10 000 → 5·10⁷ pairs ≈ $8 147 / $14 095. Encoding is per TEXT — N=10 000 ≈ $5.65 once, then local comparison at 0.85 ms/pair ≈ 11.8 CPU-hours for all pairs (embarrassingly parallel) and `semantic_fingerprint` hashing makes exact-duplicate grouping O(N). That asymmetry is the only place where an AIXL-style canonical form beats the arbiter on cost, and only where the canonical form is meaningful (controlled vocabulary: 99.4 % on its own set; on open text it proves 0–17 % and so cannot replace the arbiter).
**Untested design that follows from the numbers (not implemented, not measured):** a funnel — (1) hash `semantic_fingerprint` / canonical key to bucket candidate pairs at O(N), (2) the arbiter 2-of-2 only on candidate pairs, (3) a stored decision memo (pair hash + model + prompt id) so each pair is paid once. Its recall depends on whether the cheap key retains true paraphrases, which was NOT measured (on open text the rules key misses many).
**Limits:** proxy tokenizer; no thinking tokens counted (adaptive thinking on the judge models would add cost, unmeasured); agent wall-clock ≠ API latency; prices are cached table values, check before budgeting; one machine; the 400 pairs are controlled-vocabulary and therefore the best case for the deterministic path.

## PRE-REGISTRATION — blind12, the funnel test (written 2026-10-03, BEFORE any blind12 output exists; `data/blind10/blind12.jsonl`, sha256 4578086b…, verified)
**Why a new set:** blind10 and blind11 are spent. blind12 is a CLUSTERED corpus by two new author runs (Opus 30 clusters in hospital/logistics/DevOps/university/banking/HR/manufacturing/public-sector/e-commerce/events; Sonnet 30 clusters in legal/marketing/agri-food/energy/travel/real-estate/patient-scheduling/IT-helpdesk/accounting/nonprofit; ~25 % "simple corporate-data" requests, the rest free-form). 360 texts: **60 clusters × 4 paraphrases (same meaning; ES/EN/PT mixed, ≥1 cross-language per cluster; 205 en / 83 es / 72 pt texts in total) + 120 near-miss texts** (2 per cluster, each ONE meaningful change, each its own cluster). Ground truth = cluster id: equivalent pairs = same cluster (60 × C(4,2) = **360 pairs**); near-miss pairs = a near-miss vs the 4 paraphrases of the cluster it imitates (**480 pairs**, the hardest negatives); all pairs = 64 620.
**Question:** can a cheap, deterministic key generate candidate pairs (stage 1) cheaply and with high recall so that an arbiter (stage 2) only judges candidates? (`semantic_fingerprint` / canonical key is AIXL's only possible edge, per the cost measurement.)
**Stage 1 candidate generators (fixed now):** K1 = AIXL rules route, canonical forms equal (`compare(a,b)` with `inconclusive` off ⇒ verdict EQUIVALENT); K2 = `semantic_fingerprint(a) == semantic_fingerprint(b)`; K3 = lexical baseline (NOT AIXL): Jaccard of accent-stripped, lowercased content-word sets (function words removed) ≥ 0.2, also reported at 0.1 and 0.3; K4 = all pairs (reference). Stage-1 metrics, computed deterministically on all 64 620 pairs: candidate recall (of the 360 equivalent pairs), near-miss leakage (of the 480 near-miss pairs), candidate rate (candidates / 64 620), candidate precision.
**Stage 2:** arbiter 2-of-2 (Sonnet, Haiku; `arb_rules.txt` UNCHANGED, texts as DATA) on the 360 equivalent + 480 near-miss pairs = 840 pairs. Funnel metrics: funnel recall = equivalent pairs passing stage 1 AND judged SAME by both / 360; funnel false-SAME = near-miss pairs passing stage 1 AND judged SAME / 480; plus the arbiter alone (no stage 1) on the same 840 pairs. Cost = candidate count × the measured per-pair arbiter cost vs 64 620 × that cost.
**Stratification (fixed now):** a cluster is *controlled* iff all 4 paraphrases give `to_semantic(t).meta["unrecognized"] == []` and at least one ACTION node; K1/K2 recall is reported for controlled vs free-form clusters.
**Gates:** AIXL has a measurable prefilter role iff K1 or K2 achieves **candidate recall ≥ 80 % with candidate rate ≤ 10 %** AND beats K3 on recall at an equal or lower candidate rate. **Candidate recall < 50 %** ⇒ AIXL's key is not a useful prefilter on open text and its role is restricted to controlled vocabularies/interchange. Between: reported, no claim. False-SAME of the arbiter on near-miss pairs: reported against the earlier 0.6 %–1.7 % figures, no gate. Declared limits: cluster membership labels come from the authors (not independently verified; disputes will be listed), only 25 % simple requests, 3 languages, 360 texts; the 63 780 non-near-miss cross-cluster pairs are not judged by the arbiter (their candidate counts under K1–K3 are reported; their false-SAME rate is not measured); this set is spent after the run.
