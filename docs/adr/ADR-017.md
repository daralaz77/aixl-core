# ADR-017 — Residue canonicalizer + per-side completeness check — STATUS: DESIGN (experiments run, nothing shipped)

## Problem (evidence)
ADR-016 step 2 made loss visible (`R:`), and on blind10 the LLM route went from 58.9 % to 1.1 % false-EQUIVALENT — but **proven equivalence fell from 55/60 to 3–5/60**, because encoders copy residue in the text's original wording, so a faithful translation ("to the CFO" / "al director financiero") yields different literals. What are residue items? Measured on 743 real items (blind10, card 0.5): **76–93 % are open noun phrases**, only 15–25 % are numbers/units/weekdays/durations. A deterministic lexicon alone cannot be the main path.

## Experiments (120 real pairs: 60 EQUIVALENT + 60 NOT_EQUIVALENT, residue lists + action codes only; Sonnet; `benchmarks/residue_canon_eval.py`, data in `data/blind10/rc_*`, `rj_*`)
| Option | Mechanism | EQUIVALENT recovered | NOT_EQUIVALENT kept different | false-SAME |
|---|---|---|---|---|
| A | each side canonicalized INDEPENDENTLY to an English typed key (`recipient:cfo ; by:mon`), then key equality | 54/60 | 53/60 | 7/60 |
| B | an LLM judge decides SAME/DIFFERENT/UNSURE per pair | 53/60 (6 DIFFERENT, 1 UNSURE) | 53/60 | 7/60 |
| C | closed bilingual lexicon | not run: covers ≤25 % of items (typed ones only) | | |
**Key finding — the 7 false-SAME are the same cases in A and B and are NOT canonicalizer errors**: in ≥6 of 7 the residue is literally identical or empty (`'Refund'`/`'Refund'`, `[]`/`[]`), i.e. the differing detail ("50 vs 500 boxes", "room B vs C", "weekly vs daily") never reached R — an encoder loss upstream. The canonicalizer cannot detect what was never written; the **completeness check** must.
Pipeline simulation (card 0.5 + per-side completeness + A keys, blind10, 120 pairs, development signal): false-EQUIVALENT 2/60 in every setting; proven EQUIVALENT 5 → 24 → 37 → 45 /60 as the tolerated number of unaccounted words per text goes 0 → 3. The 2 false cases are a lexicon gap, not tolerance: single-letter values ("sala **B**/**C**", dropped because tokens < 3 chars are ignored) and ordering words ("tres días **antes**/**after** del vencimiento", treated as function words so never checked against the graph). Tolerance is therefore NOT a design parameter (it would be tuned on seen data); it must be replaced by structure (below).

## Decision
1. **Completeness is per side; equality is per canonical form.** A text is `COMPLETE` iff (a) every content word is accounted by an atom, a lexicon or an R item, **including 1–2 character tokens and digits**, and (b) every closed-class *structural marker* in the text (before/after/antes/depois, only/solo/apenas, all/todos, except/salvo, not/never/nunca, more/less than, every/cada, at least/at most) is reflected in the graph structure (negation, BEFORE/AFTER, SCOPE, QTY comparator, FREQ). Marker lexicon is closed and small (ES/EN/PT), deterministic, replaces the function-word blind spot. An INCOMPLETE side forces INCONCLUSIVE; no tolerance parameter.
2. **Canonicalizer = option A, independent per side, cached.** A separate step (or card 0.6 asking the encoder to emit canonical keys directly — to be A/B'd) maps each side's residue to typed items: `NUM/QTY(value,unit)`, `DAY`, `DUR`, `BY`, `FREQ`, `RECIPIENT`, `CHANNEL`, `SCOPE`, `OBJ` … in lowercase English. Independence is the safety property: the canonicalizer never sees the other side, so it cannot "agree" for convenience. Keys are stored in the AIXL line as typed R items (`R:"recipient:cfo","by:mon"`), so `fingerprint` (ADR-015) stays deterministic once keys exist; cache key = sha256(normalized text + model id + prompt id).
3. **Typed items are verified deterministically (tier 1), the LLM cannot override them**: numbers (digits/number words ES/EN/PT), units, weekdays, months, durations, simple deadlines are parsed by the Core and compared exactly; a mismatch there ⇒ NOT_EQUIVALENT even if the LLM key says same.
4. **Judge (option B) only as arbiter**, for pairs that are COMPLETE on both sides, equal on every non-residue dimension and tier-1 typed items, but whose open-phrase keys differ. `DIFFERENT` is always honored (downgrade); `SAME` is honored only with 2-of-2 agreement (two prompts or two models) and is recorded in a decision memo (pair hash → verdict) so it is replayable. Never used to override INCOMPLETE.
5. **Asymmetry rule (safety):** evidence to *separate* is accepted from any single source; evidence to *join* needs (completeness ∧ tier-1 agreement ∧ key equality or consensus).

## Alternatives rejected
* Pairwise judge as the main path (B): equal accuracy to A in the experiment, but costs one call per *pair* (O(n²) over a corpus), is non-deterministic per run, and sees both sides (can rationalize equality). Kept as arbiter.
* Embedding similarity: ADR-002.
* Raising the unaccounted-words tolerance: increases proven equivalence mechanically (5→45/60) but is tuned on seen data and silently reopens loss; rejected.
* Pure lexicon (C): coverage ≤25 % of items; used for tier 1 only.

## Compatibility / versioning
Additive to AIXL 0.5 (typed R items are still `R:`); old messages and 0.4 verdicts unchanged while `inconclusive` is off. New status `INCOMPLETE` appears as a warning (`INCOMPLETE_ENCODING`), and as INCONCLUSIVE when the flag is on. Fingerprint of a 0.5 line with canonical keys differs from the 0.4 one by construction.

## Validation plan (gates fixed before implementing; judge = blind11, frozen sha256 b22b863b…, evaluated ONCE after implementation; encoders Sonnet AND Haiku because the author is Sonnet)
1. false-EQUIVALENT ≤ 5 % of non-equivalent pairs (blind10 development signal: 1–2 %).
2. proven EQUIVALENT ≥ 70 % of equivalent pairs (blind10 signal after the marker fix is open: 45/60 = 75 % only with an unprincipled tolerance of 3 — the structural check must reach ≥ 70 % WITHOUT tolerance, or the gate fails and is reported).
3. 0 regressions: 453 tests, 5×100 ≥ 99 %, sil_security 57/57.
4. Report separately: Sonnet vs Haiku encoder; completeness-flag rate; judge invocation rate; cost per 100 pairs.
5. If gate 2 is not met, keep INCONCLUSIVE off by default and document (ADR-016 rule).

## Risks
* Canonicalizer variance between independent calls ("warehouse manager" vs "warehouse supervisor"): measured 54/60 for A; residual 10 % goes to INCONCLUSIVE (safe) or arbiter.
* Closed marker lexicon is ES/EN/PT only; other languages ⇒ always INCOMPLETE ⇒ safe but useless.
* Experiments used residue lists, not the full pipeline end-to-end, and were run on the same seen set used to diagnose: the numbers are optimistic until blind11.
* Cost/latency: one extra LLM call per side (cacheable); offline fallback = rule-based route + INCONCLUSIVE.

## Implementation order (stop when a gate fails)
1. Completeness check (token coverage incl. 1–2 char tokens/digits + structural markers) with tests from the 2 known false cases; measure on blind10 rules + LLM routes.
2. Tier-1 typed parsers (number words, weekdays, durations, units) with unit tests in ES/EN/PT.
3. Canonicalizer step (A) + cache + typed R items in the codec; compare on keys.
4. Arbiter (B) with 2-of-2 consensus and decision memo.
5. Card 0.6 (encoder emits keys directly) A/B vs the separate step.
6. Freeze, run blind11 once with both encoders, publish results.
