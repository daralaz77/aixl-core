# ADR-019 — AIXL 0.4 Semantic Atom layer: what was built, what the evidence supports, where the loop was stopped — STATUS: ACCEPTED 2026-10-04

## Context
The 0.4 master prompt asked to rebuild AIXL around interoperable *atoms* (identity by concept id, typed relations, graph, canonical serialization, capability negotiation, fidelity metrics, adversarial tests) instead of more syntax. The audit (this session) found the 0.3–0.5 cores had no single atom definition, a closed vocabulary that dropped what it had no slot for, positional action–argument binding, extension-less identity and no atom-level gold, so atom fidelity could not even be measured.

## Decisions
1. New package `aixl/atoms/` (does not change `aixl.compare` or the 0.3-R track). Registry-versioned; relations have enforced endpoint types; `x:` extensions are explicit and refusable; `unrepresented` is an explicit loss marker inside the message and the fingerprint (fail closed, master prompt §51).
2. Measure before extending: an **atom-level gold** (148 dev cases; annotated by 3 models; 136 unanimous) and three **unseen natural sets** (blind1/2/3, 150 each, written by Opus, annotated by Sonnet and Opus independently). Metric = per-dimension F1 + a safety-critical `core` + exact-graph rate. Fable could not be used (needs usage credits); Haiku was a much weaker third annotator.
3. Guide revisions v0.2→v0.4 were driven by annotator disagreements and by what annotators reported they could not express; each revision was re-measured on a text set the guide had not seen.
4. The deterministic extractor is kept as a **controlled-domain, fail-closed** component, not as the route for open text.

## Evidence (docs/ATOMS_EVIDENCE.md; reproducible with no model calls)
* Same-model annotators agree 98 % (correlated errors, not independence). Sonnet vs Opus: 92.6 % exact graph on dev, **32.7 % / 35.3 % / 36.0 %** on unseen natural text under guides v0.2 / v0.3 / v0.4 (the 58.7 % seen for v0.3 on blind1 is contaminated: the guide was written from those texts). F1 ≈ 0.83, core F1 0.83–0.86.
* The first +25 points on blind1 came from the guide being fitted to those texts; the true gain on unseen text is ≤ 3 points, inside the ±4-point noise at n = 150. **The loop was stopped for diminishing returns, not for completeness.**
* Rule extractor: dev 95 % exact (tuned); unseen sets F1 0.27–0.37, 0/450 declared complete, 0 silent errors; on dev every COMPLETE extraction is exact (132/132).
* Transport: cross-model round trip (sender extracts → AIXL → different model writes text → third model re-extracts): F1 0.93, core 0.97 over 40 cases in both directions — equal to the Sonnet-vs-Opus floor on the same cases (0.93 / 0.97). Caveats: n = 40, Claude models only, blind1 texts.
* Master prompt tests §33–§39 pass as unit tests on controlled-domain sentences (3-language equivalence, 150→300 only quantity, negation only modality, exception ≠ plain, condition ≠ check, three temporal forms distinct, four quantity modes distinct); tamper-in-transit gives SEMANTIC_INTEGRITY_FAILURE; unsupported concepts are reported, never substituted.
* Two instrument bugs were found by annotators, not by tests, and are now regression-tested: a double-escaped regex that rejected every TIME offset and `MM-DD` date; `Atom.from_dict` silently dropping unknown keys (now reported by `validate()`).

## What may be claimed
* AIXL atoms are a **verifiable interchange format** (identity, relations, scope, polarity, time, quantity, integrity, explicit loss) and a **measuring instrument** for what two agents understood.
* Through that format a meaning survives a cross-model hop at about the same fidelity as two independent readings of the original agree (small sample).
## What may NOT be claimed
* That free text has a unique atom graph, that two LLMs produce the same graph (35 % exact), that the rule extractor understands natural text, that dev numbers are performance, or that this beats the 2-of-2 LLM arbiter for equivalence of free-text paraphrases (ADR-018 stays the baseline for that).

## Not done / next
Blind4+ with a new author and a different annotator family when credits allow (Fable) — the real test of whether ~35 % is a property of language or of Claude-family annotators; atom-level gold adjudicated by humans; an LLM-extractor wrapper with the `validate()`/`receive()` loop and abstention; handshake over a real transport (design only, §53–54); REST API (§32) and extension registry (§52) remain design-only.
