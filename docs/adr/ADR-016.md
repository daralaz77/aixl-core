# ADR-016 — Open role slots + explicit residue (AIXL 0.5 proposal) — STATUS: DESIGN ONLY, not implemented

## Problem (evidence, E-BLIND10)
On 300 cases written by other models, both routes score 37–40 % and produce 88 (rules) / 106 (LLM) false-EQUIVALENT verdicts. Reading the encodings shows the cause is representational, not parsing: the format has slots only for a closed vocabulary (D/E nouns, T dates, H confidence, O formats), so anything else is **dropped without trace**. Hand-classification of 44 of the 88 rules-route false-EQUIVALENTs (sample, not exhaustive):
| Class | n/44 | Examples | Missing capability |
|---|---|---|---|
| A. Open role filler differs | 15 | lawyer→accountant; frontend→QA team; room B→C; AES-256→128; develop→main; $500→$1000; weekly→daily | roles with OPEN values (recipient, destination, instrument, quantity+unit, frequency) |
| B. Extra/missing detail | 17 | +"by WhatsApp"; +"double-sided"; +"before noon"; +"in euros"; +"except dev" | manner/channel/deadline/scope/exception slots, so "added" is visible → PARTIAL |
| C. Opposition on non-lexicon verbs | 12 | hire/reject; publish/hold; keep on/turn off; raise/lower 5 % | action opposition beyond ENABLE/DISABLE, INCLUDE/EXCLUDE; polarity |
Not addressed here: AMBIGUOUS (9/60 on both routes) — a separate problem (ADR candidate, needs its own evidence).

## Decision
1. **Role frame instead of more atoms.** Each action carries typed roles, values OPEN: `THEME, RECIPIENT, SOURCE, DEST, INSTRUMENT (channel/means), MANNER, QTY(value,unit,cmp), FREQ, TIME(kind: AT|BEFORE|AFTER|WITHIN|EVERY), SCOPE(include/except), CONDITION, PURPOSE`. Existing atoms are views of this frame (D≈THEME, L≈DEST/LOC, K:QTY≈QTY, T≈TIME), so 0.3 messages decode unchanged.
2. **Open values compare as normalized literals, never as "absent".** A value is `canonical-token` (if in a lexicon) or `lit:"…"` (NFKC, casefold, accents stripped, number words→digits, units normalized, stop-words removed). Equal after normalization → equal; different literals → **NOT_PROVEN_EQUIVALENT**, not EQUIVALENT. Cross-lingual literals ("la nube" vs "the cloud") are the only case needing help: they go to a lexicon/LLM canonicalizer step that may *upgrade* NOT_PROVEN→EQUIVALENT, never downgrade.
3. **Explicit residue.** Anything the encoder cannot place in a role is emitted as `R:"literal clause"`, never dropped. Residue on one side only → PARTIAL (added/removed); different residues on both sides → NOT_PROVEN_EQUIVALENT. Validator rule: an AIXL line whose source text contains content words absent from every slot and from R is flagged `UNACCOUNTED_CONTENT` (extends ADR-008 from nouns to all clauses).
4. **Verdict algebra change (safe direction).** Add `INCONCLUSIVE` (aka NOT_PROVEN): EQUIVALENT requires every role equal or provably equivalent. The default flips from "no difference seen ⇒ equal" to "no proof ⇒ not equal". This alone is expected to remove most class-A false-EQUIVALENTs, at the price of more INCONCLUSIVE on true paraphrases — to be measured, not assumed.
5. **Polarity/opposition.** Add per-action `polarity` (+/−) and an extensible opposition table (`hire/reject, publish/hold, raise/lower, keep/stop, accept/refuse, require/forbid, store-plain/encrypt` …) loaded from data, not code; encoder may assert `A:HIRE` only from the card verb table. Unknown pairs stay NOT_EQUIVALENT (never CONTRADICTORY without table or explicit negation).

## Syntax sketch (derived from the model, per master prompt §18)
`V:AIXL-0.5 I:REQUEST_EXECUTION A:SEND D:REPORT RC:@CFO FQ:WEEK TB:MON QTY:15%,UP R:"urgente"` — new atom letters are additive; unknown atoms in 0.3/0.4 decoders must be preserved as `extras` (needs a small parser change, see below).

## Alternatives rejected
* More lexicon entries (ADR-003 path): measured ceiling — the sets are open-domain; a lexicon grows without bound and still drops silently.
* Free-text "notes" field compared by LLM: breaks determinism (§3.3) and ADR-002.
* Embedding similarity: ADR-002; irreproducible.

## Compatibility & versioning
Additive atoms ⇒ AIXL 0.5 (minor), Semantic Core 0.5. 0.3/0.4 messages decode into frames with empty new roles (unchanged verdicts on the 435 existing tests and 5×100). The `INCONCLUSIVE` verdict is **breaking** for consumers that treat `equivalent=False` as NOT_EQUIVALENT: it needs a migration note and `compare()` keeps a legacy boolean (`equivalent`, true only for proven equality) so old callers err on the safe side. Fingerprints include new roles (ADR-015: version-bound) ⇒ 0.5 fingerprints differ by construction.

## Validation plan (acceptance, fixed BEFORE implementing)
1. Dev: E-BLIND10 (300 cases, already seen — used for design, so it cannot be the final judge).
2. **Final judge: a fresh set blind11 written by a THIRD model family/author not used so far, ≥300 cases, frozen before any code.**
3. Gates: false-EQUIVALENT on blind11 ≤ 10 % of non-equivalent pairs (now 70–80 %); EQUIVALENT recall ≥ 70 % (now 90 %; a drop is expected and accepted, reported openly); 0 regressions on 435 tests, 5×100 ≥ 99 %, sil_security 57/57; parse failures 0; both routes (rules, LLM-with-new-card) reported.
4. Negative control: the same card/code on blind11 *before* the change, to avoid blaming a harder set.
5. If gates fail, document and keep 0.4 as current (§37: no forcing results).

## Risks
* Literal normalization may over-split paraphrases ("weekly" vs "every week") → needs a small closed set for FREQ/QTY/TIME (those ARE closed-class) — design is open for roles whose values are open, closed lexicon for roles whose values are closed.
* Card grows (19.7 KB now); longer card may hurt weaker encoders — measure Haiku and Sonnet separately.
* Residue could become a dumping ground that hides loss (counted as "accounted"). Mitigation: residue rate reported as a metric; high residue ⇒ lower confidence and INCONCLUSIVE on equality.
* Authored-by-me design checked on data I have seen: mitigated only by gate 2.

## Implementation order (each step with tests; stop if a gate fails)
1. Verdict algebra + `INCONCLUSIVE` + legacy bool (smallest change, expected biggest effect) → re-measure on E-BLIND10 rules route.
2. Residue `R:` + `UNACCOUNTED_CONTENT` validator.
3. Role frame QTY/FREQ/TIME-kind (closed-class roles first).
4. Open roles RECIPIENT/DEST/INSTRUMENT/MANNER/SCOPE with literal normalization.
5. Opposition table + polarity.
6. Card 0.5 + LLM route re-measure; freeze blind11; final judgment.

## Step 1 implemented (2026-10-02) — INCONCLUSIVE verdict, opt-in (`config["inconclusive"]`, default **false**)
What shipped: `ComparisonResult.verdict` (EQUIVALENT | NOT_EQUIVALENT | INCONCLUSIVE); rule-based translator records `meta["unaccounted"]` (content words/numbers neither a lexicon nor the canonical form accounts for; closed-class FUNCTION_WORDS and a small cross-lingual concept table are excluded); `compare_graphs` returns INCONCLUSIVE (and `equivalent=False`) when canonical forms match but the two sides' unaccounted sets (light-stemmed) differ. Only the rule-based route fills `meta["unaccounted"]`; LLM-encoded graphs carry no such info until step 2 (`R:` residue), so for them nothing changes. Tests: `tests/test_inconclusive.py` (6), 446 total, 0 regressions with the flag off. Evaluator: `python -m benchmarks.inconclusive_eval [--off]`.
**Measured (flag on vs off; seen sets, so a development signal, NOT the final judgment — that is blind11):**
| set | false-EQUIVALENT off → on | true-EQUIVALENT proven (EQ) off → on (INCONCLUSIVE) |
|---|---|---|
| blind10 Opus | 46.7 % → 5.6 % | 63.3 % → 13.3 % (15) |
| blind10 Haiku | 51.1 % → 1.1 % | 43.3 % → 0.0 % (13) |
| own 5×100 | 0 % → 0 % | 100 % → 100 % |
| blind1–9 (703/697 pairs) | 3.1 % → 1.8 % | 69.6 % → 40.9 % (200) |
**Gate status:** false-EQUIVALENT gate (≤10 %) met on blind10; the recall gate (≥70 % *proven* equivalence) is NOT met (blind1–9: 40.9 %), as the ADR warned could happen — the system now says "not proven" for 200/697 true paraphrases instead of silently saying "equal". That is the intended direction (safe), but it is real cost, and part of it is accounting gaps (cross-lingual cognates like comparison/comparación, synonyms such as fail/not pass) that no lexicon patch should chase (ADR-003). Therefore the flag stays OFF until step 3/4 and an LLM/lexicon canonicalizer can upgrade INCONCLUSIVE→EQUIVALENT. Default remains the 0.4 behaviour.
Honest limits: the FUNCTION_WORDS and concept lists were extended after looking at blind1–9/dev failures (tuned on seen data); blind10 was used to diagnose, so the numbers above are optimistic for the false-EQUIVALENT side until blind11 confirms.

## Step 2 implemented (2026-10-02) — `R:` residue atom, UNACCOUNTED_CONTENT lint, card 0.5
Shipped: atom `R:` (frame field `residue`, graph node type `RESIDUE`, canonical dimension `residue` = order-free light-stemmed content words), additive to AIXL 0.3 syntax (old messages unchanged; 453 tests); `lexicon_gaps.unaccounted_content(text, graph)` doubles as a lint for ANY encoding (rule-based or LLM): content words in the source text that neither the lexicon, the canonical form nor the residue accounts for; `compare_graphs` returns INCONCLUSIVE (flag on) when the only difference is two different residues; `data/llm_translator/card_0.5.md` = card 0.3 + a completeness rule for R. blind11 frozen (below).
**Measured on blind10 (seen, development signal), LLM route, Sonnet, 6 fresh agents each:**
| configuration | false-EQUIVALENT (of 180 non-eq. pairs) | true-EQUIV proven (of 60) | INCONCLUSIVE |
|---|---|---|---|
| card 0.3, 0.4 verdicts | 106 = 58.9 % | 55 | – |
| card 0.3 + unaccounted lint, flag on | 9 = 5.0 % | 4 | 51 |
| card 0.5 (R:), flag off | 2 = 1.1 % | 5 | 0 |
| card 0.5 (R:), flag on | 2 = 1.1 % | 3 | 48 |
**Reading:** R makes the loss visible (the encoder emitted R in ~295 of 540 lines, 0 parse failures) and the dangerous error is gone on this set. But **proven equivalence collapses (55 → 3–5 of 60)**: encoders copy residue in the text's ORIGINAL wording, so a faithful translation or paraphrase ("weekly" vs "cada semana", "to the CFO" vs "al director financiero") gives different residues → not provable. This is the exact trade ADR-016 predicted; it also shows the remaining blocker precisely: **a residue canonicalizer** (cross-lingual/paraphrase equivalence of residue literals) that upgrades INCONCLUSIVE→EQUIVALENT only on evidence. Until then the flag stays OFF and the LLM route is safe-but-not-useful on open text.
