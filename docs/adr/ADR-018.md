# ADR-018 — AIXL 0.5 scope: exact engine for controlled vocabularies + loss detector + interchange/audit layer around an arbiter — STATUS: ACCEPTED 2026-10-03

Decided by the project owner on 2026-10-03 ("cerremos con el alcance recomendado") after ADR-016/ADR-017 and the blind10/blind11/blind12 experiments.

## Problem
AIXL 0.3/0.4 was positioned as a way to represent meaning and prove that two instructions mean the same. Measured on text written by other authors, that does not hold for open-domain text: the rule-based and LLM-encoded routes judged 40–59 % of non-equivalent pairs equivalent (the closed vocabulary drops what it has no slot for), and every AIXL-side repair that stays safe proves only 0–32 % of true paraphrases (docs/EVIDENCE.md). A strict full-text LLM arbiter (two independent judges, "same" only if both agree) recovers 99.7–100 % of true paraphrases with 0 % false "same" on 480 hard near-misses, repeatably (flips 1.2 %) and cheaply (≈ $0.28 per 1 000 pairs).

## Decision — what AIXL 0.5 is
1. **An exact, offline, free comparison engine inside a controlled vocabulary** (the rules route: canonical graph, comparator, diff, drift, fingerprint, negotiation, 0.85 ms/pair). Its guarantee is stated *within the vocabulary*; outside it, it is not a prover.
2. **A loss detector that refuses to say "equal" without proof**: opt-in `config["inconclusive"]` (completeness, structural markers, `R:` residue). Default stays **off** in 0.5 so existing verdicts do not change; callers that handle open text should turn it on. Revisit the default in 0.6 with a measured effect on controlled-vocabulary use.
3. **Deterministic input hygiene**: `sanitize_input` (invisible characters, compatibility forms, mixed-script homoglyphs), recorded for audit.
4. **An interchange format and transports**: the AIXL line (`V:AIXL-0.3`, additive `R:`), MCP and A2A servers, the bounded negotiation protocol.
5. **An audit layer around a full-text arbiter** (new, `aixl/arbiter.py`): the versioned arbiter rules (`data/arbiter/rules_v1.txt`, id = sha256), the 2-of-2 consensus rule ("same" needs ≥ 2 valid judges, all SAME; any DIFFERENT blocks it), validation of a judge's output (missing/invalid lines), and an append-only **decision memo** (pair key over RAW texts + rules id + judge names; texts stored only as hashes unless requested; `sanitize_input` findings recorded). Judges are caller-supplied functions: **no provider is imported and the core never calls an LLM**. Rationale: arbiter errors are systematic and single pairs can flip between runs, so a decision must be stored and reused, not re-derived (ADR-017 repeatability).

## Decision — what AIXL 0.5 does NOT claim (claims withdrawn)
* That any AIXL route proves equivalence of free-text paraphrases. Use the arbiter for open text.
* That AIXL's canonical key/fingerprint is a useful candidate-pair prefilter on open text (recall 15.8 % vs 60.3 % for plain lexical overlap, blind12).
* That the LLM route is "recommended for production" (withdrawn in `auto.py`; 37.0 % on other authors' text).
* That rules-route ambiguity detection works on free text (16.7 % recall, 11.7 % false flags).
* Compression (AIXL is ≈ +246 % tokens), superiority over MCP/A2A/JSON or over a strict LLM judge, "standard", "universal".
* That the 99.4 % / 95 %+ figures are general accuracy (same-author or card-vocabulary sets; archived in docs/HISTORY.md).

## Compatibility and version
* Package version **0.5.0** (MINOR while MAJOR is 0, per VERSIONING_POLICY: new capabilities + one additive canonical dimension). Wire token **stays `V:AIXL-0.3`**; `R:` is additive; readers built before `R:` reject a line that contains it.
* **Fingerprints stay stable**: an empty `residue` dimension is omitted from `canonical()`, so every graph without residue keeps exactly its 0.4.0 canonical form and fingerprint (pinned by a golden test: `Envía el informe a Ana en PDF.` with `today=2026-10-03` → `4d601cd77a368a82`). Found and fixed during this release: an always-present empty `residue` had changed every fingerprint.
* `inconclusive` default off ⇒ no verdict changes for existing callers; new `ComparisonResult.verdict` field is additive.

## Release gates met
479 tests (incl. `test_arbiter.py` 16, doc tests, golden fingerprint pin) green on a clean checkout whose directory is not named `aixl-core`; CI green on the previous push; frozen sets verify against their sha256; docs updated (README, SKILL.md, EVIDENCE.md, ARCHITECTURE, PROTOCOL, API_REFERENCE, SEMANTIC_CHANGELOG).

## Consequences / what would change this decision
* Revisit if: judges from other vendors change the arbiter's error profile (untested); an embedding-based blocker beats the lexical baseline; real agent-to-agent traffic shows a different failure distribution; a canonical form with open role slots (ADR-016 steps 3–5) is built and passes a fresh, pre-registered set. blind10, blind11 and blind12 are spent — any new claim needs a fresh set and gates written first.
* Known gaps carried into 0.5: arbiter order-symmetry not measured (the memo key is ordered on purpose); injection resistance measured on one red-team author; no cross-vendor judges; costs are estimates.
