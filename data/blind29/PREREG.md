# blind29 (about 120 pairs) — pre-registration, written 2026-11-11 BEFORE the pairs exist
Purpose: a PAIRED, FRESH test of three comparator changes made after blind28 (2026-11-11, uncommitted in the aixl-core working tree, tests in tests/test_semantic_recall_2026_11_11.py): (1) fixed deadline phrasings ('no later than X' = 'by X', 'by X at the latest' = 'by X', 'no máximo até' = 'até', 'no después del' = 'hasta el'), (2) a fronted time/frequency adjunct is moved to the end ('After C, do A' = 'Do A after C', 'Mañana, X', 'Cada semana, X', 'Every Monday, X'), (3) two ledger entries: 'never/nunca/jamás' and 'qualquer/cualquier' on one side only make EQUIVALENT impossible. Rules (1) and (2) target recall, rule (3) targets safety. They were designed by reading blind28, which is now spent; on blind28 itself they gave 29 of 60 equivalents proven (was 24) and 2 of 60 false accepts (was 4): that is DEVELOPMENT evidence and proves nothing.
Design: new authors write new pairs; the SAME pairs are run through the OLD comparator (git commit 933fb76, extracted unchanged) and the NEW comparator (the frozen working tree); two blind Claude judges (Opus, Sonnet; arbiter_rules_v1.txt verbatim; no local model: Qwen proved useless on blind28) are asked once. This makes the comparison paired: any difference between OLD and NEW is due to the change, not to the sample.
Constructs, authors, labels: the same 10 in-vocabulary constructs, schema and label definitions as blind28 (bounds, exception/unless, only, negation forms, if/unless order, number forms, deadline direction, verb synonyms, word order/voice, quantifiers); three fresh agents Opus (P001-P040), Sonnet (Q001-Q040), Haiku (R001-R040), who see nothing about AIXL, blind28 or any result; about 20 EQUIVALENT / 14 NOT_EQUIVALENT / 6 UNDECIDABLE each; es / en / pt mixed. Labels are the authors' and are not corrected. G1 counts UNDECIDABLE as non-equivalent.
Frozen: SHA-256 of the NEW code files (semantic/*, hybrid_protocol.py, arbiter.py, arbiter_rules_v1.txt) and of the OLD code files go into CODE_FREEZE.json before the judges run; author files go into MANIFEST.json. One run; the evaluator refuses a second run; the result file is written with an editor tool.

Systems and metrics (fixed now):
 OLD comparator alone; NEW comparator alone; NEW AND Opus AND Sonnet SAME (R1-new); the judges alone (Opus, Sonnet, both).
 Per system: false accepts over the NOT_EQUIVALENT-labelled pairs (UNDECIDABLE included), proven-EQUIVALENT over the EQUIVALENT-labelled pairs, wrong NOT_EQUIVALENT over the EQUIVALENT-labelled pairs.
 Paired: pairs newly proven by NEW (OLD not, NEW yes), pairs lost (OLD proven, NEW not), new false accepts (NEW accepts, OLD did not), false accepts removed.
Decision rules (fixed now):
  IMPROVEMENT of recall is real only if NEW proves at least 5 more EQUIVALENT-labelled pairs than OLD (net, paired) AND adds 0 new false accepts. 5 of ~60 is about 8 percentage points.
  IMPROVEMENT of safety is real only if NEW has fewer false accepts than OLD and none new.
  G1 for NEW (reported, decides any safety claim): NEW false accepts <= 3% of the non-EQUIVALENT-labelled pairs (about 1 of 60); R1-new reported alongside, with the vacuity floor of 10 proven pairs.
  Any new false accept by NEW that OLD did not have is reported first and counts against the change.
Claim policy: if the recall rule holds: "on N fresh sentences of the comparator's constructs, the changed comparator proved k more equivalent pairs than the previous version, with no new false accept". It is not a generalisation claim (in-distribution constructs, model authors, small sample). If a rule fails, it is reported as failed and the change is reverted or narrowed.
Expectations written beforehand: NEW proves 3-8 more equivalents than OLD (the fronted-adjunct and deadline rules fire on only a fraction of fresh sentences, so I expect the net gain to be smaller than on blind28); NEW adds 0-1 new false accepts; OLD and NEW both have 2-5 false accepts of 60 (every set has found a new hole), so G1 for NEW will probably FAIL even if the paired comparison is favourable. The two Claude judges will again have 3-10% false SAME, mostly on UNDECIDABLE labels.
Honest limits: tuned constructs; model authors and labels; about 120 pairs; the rules were written after seeing blind28's sentences, so fresh authors writing the same kind of sentence are the test, not new constructs; judges are Claude models.
