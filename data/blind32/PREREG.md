# blind32 (60 pairs, bounds only) — pre-registration, written 2026-11-17 BEFORE the pairs exist
Purpose: a PAIRED, FRESH test of ONE closed lexicon entry written after reading blind28-blind31 (committed ead783d on a working branch): the English phrase "no fewer than" is a quantity bound meaning the same as "at least" (QTY_PHRASES in aixl/semantic/lexicon.py). On the spent sets it proves 3 more equivalent pairs (blind26-blind31: 119 -> 122 of 237) and adds no false accept; written by reading those sets, so that is DEVELOPMENT evidence only.
History (reported, not hidden): the round started with three entries ('no fewer than'; 'jamais' as a negation word; 'com exceção de/do/da/dos/das' as an exception phrase). An independent adversarial audit of 440 pairs found false accepts introduced by the last two ('Se jamais vir o erro' = 'Se nunca vir o erro', 'com exceção do tipo X', the number of an excepted set, 'jamais' inside English); the 'no fewer than' entry produced none. The two failing entries were REMOVED before this registration; they are not tested here. The audit set is spent.
Design: the SAME fresh pairs go through the OLD comparator (main commit 04e9574, extracted unchanged) and the NEW comparator (branch head, files frozen by SHA-256). Paired, so any OLD/NEW difference comes from the entry, not the sample. NO judges this time (cost proportional to a one-phrase change): metrics use the authors' labels only; no R1-new / judge numbers are reported.
Authors: three fresh agents (Opus K001-K020, Sonnet L001-L020, Haiku M001-M020), told nothing about AIXL, earlier sets or results; they get the construct description (bounds: at least / no fewer than / minimum; at most / up to / no more than / maximum), the label definitions, the schema and the counts. ONLY this construct, 20 pairs each, 60 total; about 50% EQUIVALENT, 35% NOT_EQUIVALENT, 15% UNDECIDABLE; es / en / pt mixed. Labels are the authors' and are never corrected; UNDECIDABLE counts as non-equivalent.
Frozen: SHA-256 of the NEW and OLD code files go into CODE_FREEZE.json and of the author files into MANIFEST.json before the evaluation. One run; the evaluator refuses a second run. The SHA-256 of this file is in PREREG.sha256, taken before the authors were launched.
Metrics (fixed now): per system (OLD, NEW): false accepts over the non-EQUIVALENT-labelled pairs; proven-EQUIVALENT over the EQUIVALENT-labelled pairs. Paired: newly proven, lost, new false accepts, false accepts removed. Reported overall and per language; pairs whose text contains 'no fewer than' reported separately.
Decision rules (fixed now):
  R-recall: NEW proves at least 2 more EQUIVALENT-labelled pairs than OLD (net, paired) AND adds 0 new false accepts. The bar is +2 (not +5 as in earlier rounds) because the change is one phrase in one construct and 20-30 equivalent pairs are expected.
  R-safety: NEW adds no false accept; any false accept NEW has and OLD did not is reported FIRST and counts against the change.
  G1 for NEW (reported): NEW false accepts <= 3% of non-EQUIVALENT-labelled pairs (about 1 of ~30 here: bound 1).
Claim policy: if R-recall and R-safety hold: "on N fresh sentences of the bounds construct, the changed comparator proved k more equivalent pairs than main, with no new false accept". If R-recall fails it is reported as failed and the change is not merged. Never a generalisation claim (one construct, model authors, 60 pairs).
Expectations written beforehand: NEW gains 1-3 proven pairs (only English pairs that use 'no fewer than' and are otherwise provable; in blind28-31, 4 of ~12 equivalent bounds pairs used it and 3 of those became provable); R-recall (+2) has roughly one chance in two; 0 new false accepts is likely (~90%): the audit found none for this entry in about 100 adversarial pairs. OLD and NEW each have 0-2 false accepts of ~30.
Honest limits: tuned construct and entry written after reading the previous sets; model authors and labels (authors are Claude models told not to use any tool except one Write: an instruction, not a technical isolation); 60 pairs; no judges; one run.
