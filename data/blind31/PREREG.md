# blind31 (120 pairs) — pre-registration, written 2026-11-16 BEFORE the pairs exist
Purpose: a PAIRED, FRESH test of ONE comparator rule written after reading blind28, blind29 and blind30 and hardened with an independent adversarial audit (committed 4269a66 on a working branch; tests in tests/test_semantic_voice.py): a REGULAR-participle passive with 'by' ('Los anticipos son aprobados por el departamento', 'Every payment must be approved by the auditor') is proven equal to its active sentence only inside a closed shape: present-tense copula (is/are/es/son/be/ser) + regular participle of a lexicon verb + 'by/por'; the active text has the same verb in the simple present; and, once the verb, the copula and 'by' are removed, the two texts contain EXACTLY the same words with the same spelling (articles, plural forms, possessives, demonstratives, clitics, time phrases, modals); no question mark; no quantifier or number inside the agent; no coordination; no means noun (email, phone ...); the ordinary slot-by-slot comparison still has to find every slot equal and the roles in the same order. On the spent sets it proves 3 more equivalent pairs (blind26-blind30: 94 -> 97 of 180) and adds no false accept; it was written by reading those sets, so that is DEVELOPMENT evidence only. Its first version had 12 false accepts found by an independent auditor on 259 adversarial pairs (that audit set is also SPENT); the closed shape above is the version tested here.
Design: the SAME fresh pairs go through the OLD comparator (git tag v0.7.1, extracted unchanged) and the NEW comparator (commit 4269a66, frozen by SHA-256), and through two blind Claude judges (Opus, Sonnet; arbiter_rules_v1.txt verbatim). Paired, so any OLD/NEW difference comes from the change, not the sample.
Authors: three fresh agents (Opus W001-W040, Sonnet X001-X040, Haiku Y001-Y040), told nothing about AIXL, any earlier set or any result; they get only the construct list, the label definitions, the schema and the counts. The same ten in-vocabulary constructs and label definitions as blind28-blind30, but word_order_voice is deliberately OVER-SAMPLED: 13 pairs per author (at least 6 of them active-versus-passive), the other nine constructs 3 pairs each (13 + 27 = 40). Total 120: voice 39, other constructs 81; about 50% EQUIVALENT, 35% NOT_EQUIVALENT, 15% UNDECIDABLE; es / en / pt mixed. Labels are the authors' and are never corrected; G1 counts UNDECIDABLE as non-equivalent.
Frozen: SHA-256 of the NEW and OLD code files go into CODE_FREEZE.json, the author files into MANIFEST.json, before the judges run. One run; the evaluator refuses a second run; the result file is written with an editor tool. The SHA-256 of this file is in PREREG.sha256, taken before the authors were launched.

Metrics (fixed now): per system (OLD, NEW, NEW AND both judges SAME, judges alone): false accepts over the NOT_EQUIVALENT-labelled pairs (UNDECIDABLE included), proven-EQUIVALENT over the EQUIVALENT-labelled pairs. Paired: pairs newly proven by NEW, pairs lost, new false accepts, false accepts removed. Everything is reported overall, for the TARGETED construct (word_order_voice) and for the NINE OTHER constructs together; per language and, inside word_order_voice, active-versus-passive pairs separately where the author's text allows it.
Decision rules (fixed now, same bar as blind29/blind30):
  R-recall: on word_order_voice, NEW proves at least 5 more EQUIVALENT-labelled pairs than OLD (net, paired) AND adds 0 new false accepts overall.
  R-noharm: on the nine other constructs NEW adds 0 new false accepts and loses at most 1 proven pair.
  R-safety: NEW has no new false accept anywhere; any false accept that NEW has and OLD did not is reported FIRST and counts against the change.
  G1 for NEW (reported, decides any safety claim): NEW false accepts <= 3% of the non-EQUIVALENT-labelled pairs (about 1 of ~58); R1-new (NEW AND both judges) reported with the vacuity floor of 10 proven pairs.
Claim policy: if R-recall and R-noharm hold: "on N fresh sentences of the comparator's constructs, the changed comparator proved k more equivalent pairs than v0.7.1 in the active/passive construct, with no new false accept". If a rule fails it is reported as failed and the rule is reverted or narrowed in the patch handed to the user. Never a generalisation claim (in-distribution constructs, model authors, over-sampled target, small sample); the overall gain is inflated by the over-sampling and the 'other constructs' line is the honest check.
Expectations written beforehand: NEW gains 1-4 proven pairs in word_order_voice (the closed shape needs a simple-present active, a regular participle, a present copula and identical wording otherwise; Portuguese is inert because 'pelo/pela' are not read as 'by'; English active present is only partly recognised), so R-recall (+5) has roughly one chance in four of holding; 0 new false accepts is likely (about 80%) because an independent audit already removed 12 holes, but every earlier set found a new hole; OLD and NEW each have 0-3 false accepts of ~58; the two judges 7-12% false SAME, mostly on UNDECIDABLE labels.
Honest limits: tuned construct and rule written after reading the previous sets; hardened on an audit set that is now spent; model authors and labels (authors are Claude models, not isolated by tooling beyond their instructions); 120 pairs; two Claude judges that agree on almost everything; over-sampling of the target.
